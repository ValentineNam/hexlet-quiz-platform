## Интерактивность

Проверены нативные клавиатурные действия, переданные через CDP: Tab к radio, ArrowRight к Марсу, Tab и Enter для отправки; Tab/Enter для перехода; Space для checkbox Дельфин и Летучая мышь, Enter для отправки. Результаты — 1000 и 1500 баллов. Фокус после ответа переносится в feedback, после перехода — в заголовок вопроса.

Третий вопрос оставлен без ответа: после ожидания 5.5 секунды реального времени отображается «Время истекло», получено 0, поля заблокированы. Итоги: 2500 из 3000, 2 правильных ответа из 3, пройдено 3 вопроса. Клавиатурный перезапуск вернул первый вопрос, отсутствие выбранных radio и таймер 30 секунд.

При эмуляции prefers-reduced-motion: reduce matchMedia вернул true, вычисленный transition-duration варианта — 0s.

Первоначальные попытки клавиатурного сценария не прошли из-за сценария проверки: лишняя стрелка и неполная передача Enter через CDP. Исправлены только команды временного проверочного скрипта; после корректной передачи keycode/text полный проход успешен. Это не заявляется как исправление дефекта приложения.

## Исправление включённого дедлайна после аудита — 04.11.2026

Предыдущий браузерный проход и скриншоты выше относятся к первоначальной реализации. В этой точечной правке новый браузерный/визуальный проход не выполнялся; добавлены автоматические проверки с контролируемым performance.now и интервалами.

| Контролируемый сценарий первого вопроса                    | Ожидаемый результат                                                             |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Выбран Марс, отправка в 29999 мс                           | accepted, 500 баллов                                                            |
| Выбран Марс, отправка в 30000 мс                           | accepted, 500 баллов                                                            |
| Выбран Марс, отправка в 30001 мс при задержанном интервале | late / timeout, 0 баллов                                                        |
| Интервал или visibilitychange в 30000 мс                   | 0 секунд, форма остаётся открытой; пояснение точной границы                     |
| visibilitychange в 30001 мс                                | timeout, управление заблокировано                                               |
| Refresh и submit на дедлайне в обоих порядках              | Одна оценка, 500 баллов; поздние события не переписывают результат              |
| Timeout раньше повторного submit                           | Остаётся timeout / 0, повторной оценки нет                                      |
| Обычное размонтирование и StrictMode                       | Все обработчики visibilitychange удалены с идентичными ссылками, интервалов нет |

Новые проверки сначала выполнены на старом коде: 7 падений из 30 тестов. После исправления frontend предварительно: 30/30 прошли. Во временной копии намеренно удалён removeEventListener для проверки чувствительности новых тестов. Фактический результат mutation и полного прогона — [свидетельство исправления](../practice/PM01/evidence/004-deadline-fix.md), [лог](../practice/PM01/evidence/004-deadline-checks.txt). Реальных устройств, скринридера и новой оценки контрастности в этом дополнении не было.

Итог исправления: все 30 frontend-тестов прошли, 308 тестов во всём проекте прошли. Удаление cleanup во временной копии дало 2 падения тестов идентичности обработчиков, остальные 28 прошли. Lint/typecheck/build/format:check и git diff --check успешны.
