# Задача 001 — Каркас Quiz Platform с учётом ПМ01

**Дата постановки:** 04.11.2026. **Приоритет:** срочно, первый этап колледжной практики заканчивается 08.11.2026.

## Контекст

Рабочий репозиторий: `ValentineNam/hexlet-quiz-platform`. В корне уже есть `README.md`, `.gitignore` (шаблон Node), `LICENSE` (MIT), ветка `main`. Не инициализировать Git заново и не удалять существующие файлы. Пользователь уже создал каталоги `docs/requirements`, `docs/tasks`, `docs/practice/PM01`, `PM02`, `PM04` (пустые каталоги Git не отслеживает). Полное ТЗ должно находиться в `docs/requirements/TECHNICAL_SPEC_v1.0.md`; если его нет, сообщить об этом и не придумывать содержимое.

Текущая локальная среда: macOS, Git 2.43.0, Docker CLI 29.5.2, Node 23.3.0, Corepack 0.29.4. Node 23 не использовать как целевую версию; выбрать поддерживаемую LTS (предпочтительно 24), указать способ переключения Node и согласовать версии с CI. Не менять глобальную установку Node без разрешения.

**Граница задачи:** только каркас и минимальный проверяемый вертикальный срез. Не пытаться за один заход реализовать всё ПМ01 или весь MVP.

## Порядок работы

1. Сначала обследуй репозиторий, покажи короткий план, выбранные версии и будущую структуру. Укажи блокеры, если они есть.
2. Настрой pnpm workspaces с `apps/web`, `apps/api`, `packages/shared`. В web — React + Vite + TypeScript + Tailwind, адаптивная стартовая страница с заголовком Quiz Platform. В API — NestJS и `GET /health`, возвращающий `{ "status": "ok" }`. В shared — минимальный экспорт без неутверждённых контрактов.
3. Настрой корневые команды `dev`, `build`, `lint`, `typecheck`, `test`, `format:check`, фиксированные совместимые версии Node/pnpm и lockfile. Добавь `.editorconfig`, конфигурацию форматирования и проверки стиля.
4. Добавь `docker-compose.yml` только для локальной PostgreSQL с volume, без настоящих секретов. API пока не должен зависеть от БД. Если Docker Engine недоступен, сообщи, а не заявляй об успешном запуске.
5. Настрой GitHub Actions для lint, typecheck, test, build, format:check. Сохрани существующую лицензию и дополни README точными инструкциями запуска и проверок.
6. Подготовь папки `docs/architecture`, `docs/design`, `docs/testing`, `docs/progress`, `docs/practice/PM01/evidence`, `docs/practice/PM02/evidence`, `docs/practice/PM04/evidence` с осмысленными README/.gitkeep. В `docs/practice/PM01/progress.md` создай журнал с таблицей: фактическая дата, задача, изменения, команды проверки, результат, commit SHA (если есть), путь к доказательству. Не заполняй будущие или прошлые даты вымышленными работами.
7. Добавь тест API `/health` и хотя бы один содержательный тест frontend (например, отображение заголовка стартовой страницы). Приоритет — надёжный bootstrap, не количество тестов.
8. Проверь `.gitignore`: `.env`, локальные секреты, node_modules, dist, coverage, временные файлы. Пример `.env.example` допустим только без действующих секретов.

## Ограничения

- Не реализовывать авторизацию, квизы, расчёт баллов, WebSocket, Prisma-модели, загрузку изображений и деплой — это отдельные задачи.
- Не менять функциональные требования ТЗ самостоятельно.
- Не добавлять Nx, Turborepo, Redis, Kubernetes, микросервисы без обоснованной необходимости.
- Не делать `git commit`, `git push`, PR, публикацию или платные операции без разрешения пользователя.
- Не изменять системные настройки Mac без согласования.
- Не фабриковать результаты тестов, скриншоты, даты, отладку или содержание отчётов колледжа.

## Критерии приёмки

- На совместимой Node LTS: `pnpm install --frozen-lockfile`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`, `pnpm format:check` проходят.
- `pnpm dev` запускает frontend и API, `/health` отвечает HTTP 200 с ожидаемым JSON.
- `docker compose config` валиден; запуск БД проверяется только при работающем Docker Engine.
- CI повторяет локальные проверки и не требует секретов.
- README содержит точные команды; текущие `README.md`, `.gitignore`, `LICENSE` сохранены/обновлены без потери лицензии.
- Журнал ПМ01 содержит только реально выполненную работу и воспроизводимые свидетельства.
