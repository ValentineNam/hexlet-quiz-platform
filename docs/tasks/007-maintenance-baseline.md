## Сценарий

[scripts/diagnostics/007-baseline.py](../../scripts/diagnostics/007-baseline.py) использует Python standard library и существующие node/pnpm/docker. Никаких новых package dependencies. Требуются macOS ps/lsof, локальный Docker и свободные loopback-порты. Путь до репозитория определяется по расположению скрипта.

```sh
nvm use
pnpm install --frozen-lockfile
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm format:check
python3 scripts/diagnostics/007-baseline.py --date 2026-11-23 --requests 50 --repeats 3
git diff --check
```

При повторении указать фактическую дату. Скрипт предполагает уже собранный API; выводит собственные результаты в docs/practice/PM04/evidence, дописывает checks, заменяет основной results JSON. Для сохранения новой независимой серии следует указать --output с отдельным каталогом. Не использовать --output для перезаписи исторических свидетельств без сохранения копии. Параметры ограничены: requests 5–100, repeats 1–3, параллелизм фиксирован 1/4. При максимуме — 1200 измеряемых HTTP-запросов, без неограниченного запуска.

1. Проверить ошибки PORT/URL/недоступной БД.
2. Создать собственный postgres:17.6-alpine без пользовательского volume, с лимитом 2 CPU / 512 MiB; закрепить свободный host port на 127.0.0.1. Имя случайное quiz007-\*, label quiz-diagnostics=007.
3. Проверить readiness PostgreSQL, schema validate, migrate deploy/status/повтор deploy и 4 настоящих DB-теста.
4. Запустить собранный API без enable-флага и URL: health200, маршрут квиза404. Затем включить API, проверить bind lsof, POST201/GET200, JSON/UUID/body limit/валидацию. Запустить Vite на отдельном порту без credentials БД и проверить proxy GET.
5. Прогреть 10 GET + 10 POST. Выполнить 3 × 4 ячейки по 50 запросов, максимум 4 одновременно. Снять ps/dockers stats без остановки пользовательских процессов.
6. Остановить только тестовую БД, проверить GET/POST503 и health200. Запустить её обратно на том же порту, прочитать ранее записанный квиз и выполнить новый POST без перезапуска API.
7. Остановить собственные API/Vite и удалить только свой контейнер. Сохранить JSON, сырые длительности и журналы.

## Фактический результат

Новый полный quality-прогон: frozen install, lint, typecheck, test, build, format:check, diff --check — exit0, 407 обычных тестов (277 shared + 97 web + 33 API). Дополнительно заново прошли 4 integration-теста на настоящей PostgreSQL. В двух диагностических попытках это один и тот же набор четырёх тестов, не восемь новых тестов.

Первый стенд использовал автоматический Docker host port; после stop/start восстановление не подтвердилось. Контрольный эксперимент показал смену порта 32777→32778. Исправлен только стенд: свободный порт закреплён явно, после restart проверяется его неизменность. Первый результат сохранён отдельно, не включён в итоговую таблицу и не выдан за дефект Prisma. Вторая полная серия: 600/600 измеряемых запросов, 0 ошибок; БД восстановилась за 0,606 с, API не перезапускался, подтверждённый квиз сохранён.
