# Задача № 002 — валидация вопросов квиза

Дата выполнения: 04.11.2026 (Europe/Moscow). ПМ01 — разработка программных модулей. Основание: пользовательская постановка задачи № 002 и QUIZ-03–05 технического задания v1.0. Дополнение текущей задачи разрешает вопрос только с изображением. Исходный текст ТЗ не изменён.

## Объём и публичный интерфейс

Независимый модуль в `packages/shared/src/question-validation.ts`, экспорт через `packages/shared/src/index.ts`:

```ts
validateQuestion(input: unknown): ValidationResult;
```

Экспортированы `QuestionType`, `AnswerOption`, `Question`, `ValidationErrorCode`, `ValidationField`, `ValidationError`, `ValidationResult`. Успех: `{ success: true, data: Question }`; ошибка: `{ success: false, errors: ValidationError[] }`. Дискриминант `success` позволяет безопасно сузить тип результата.

| Поле                   | Вход и нормализация                                                                           |
| ---------------------- | --------------------------------------------------------------------------------------------- |
| `type`                 | Только `single` или `multiple`                                                                |
| `text`                 | Необязательная строка; trim, при отсутствии — пустая строка                                   |
| `image`                | Необязательная строка идентификатора/ссылки; trim, пустая строка исключается из результата    |
| `options`              | Массив из 2–6 объектов, порядок сохраняется                                                   |
| `options[i].id`        | Строка до 256 кодовых единиц UTF-16 до trim; после trim непустая и уникальная, регистр значим |
| `options[i].text`      | Непустая строка после trim                                                                    |
| `options[i].isCorrect` | Только boolean, без приведения типов                                                          |
| `timeLimitSeconds`     | Конечное целое число, 5–120 включительно                                                      |
| `maxPoints`            | Конечное целое число, 100–2000 включительно                                                   |

Непустыми после trim должны быть `text` либо `image`, допускаются оба. Неверный тип любого переданного поля отклоняется, даже при наличии другого содержимого. `null` не трактуется как отсутствие строки. Неизвестные поля не копируются. Пропущенные таймер, баллы и варианты — ошибки; значения по умолчанию QUIZ-04 предназначены для будущего редактора, валидатор их не подставляет.

Типы с `isCorrect` предназначены для авторской валидации. Это не контракт данных участника: передача признаков правильности участникам до закрытия вопроса запрещена ТЗ.

## Алгоритм

1. Проверить, что вход — ненулевой объект, не массив. При неверном корневом типе вернуть единственную ошибку поля `$`.
2. Проверить тип вопроса, нормализовать строки содержимого, потребовать текст либо изображение.
3. Проверить числовые типы, целочисленность и диапазоны таймера и баллов, без преобразования строк в числа и без округления.
4. Проверить массив и количество вариантов. Если длина вне 2–6, добавить только OPTION_COUNT / options для этого массива; не читать его элементы и не считать правильные ответы. Сохранить независимые ошибки уже проверенных полей. Только для длины 2–6 индексным проходом проверить каждый вариант, включая пустые позиции разреженного массива. Нормализовать строковые поля. Через Set выявить повторные нормализованные id; ошибка указывает на повторный вариант.
5. Сосчитать строго булевы `true`. Для single требуется ровно один, для multiple — минимум два. Если объект варианта или признак правильности некорректен, не выдавать зависимую ошибку количества правильных ответов; остальные ошибки собираются.
6. При ошибках вернуть их массив без частично нормализованных данных. Иначе создать новый объект вопроса, новый массив и новые объекты вариантов. Исходные данные не изменяются, вложенные ссылки результата отделены от входа.

Для массива недопустимой длины проверка вариантов занимает O(1) времени и памяти: одна ошибка независимо от длины. Для допустимой длины время и дополнительная память — O(n + s), где 2 ≤ n ≤ 6, s — суммарная длина обрабатываемых строк. Нормализация содержимого вопроса выполняется независимо от количества вариантов. Модуль синхронный, без I/O, фреймворков, состояния между вызовами и внешних библиотек валидации. Граница — значения данных (например, результат JSON.parse); выполнение произвольных getter/Proxy из стороннего JavaScript не изолируется.

## Структура ошибок

`code` — типизированный машинный код; `field` — типизированный путь с нулевым индексом варианта; `message` — непустое русское пояснение. Путь `$` обозначает весь вход. Ошибка отсутствующего содержимого привязана к `text` и поясняет возможность изображения. Ошибки количества относятся к `options`. Проверяющий код должен опираться на code/field, а не разбирать текст сообщения.

| Код                     | Значение                                                            |
| ----------------------- | ------------------------------------------------------------------- |
| `INVALID_TYPE`          | Неверный тип корня, поля или варианта                               |
| `REQUIRED`              | Нет содержимого вопроса либо пустая строка id/текста варианта       |
| `INVALID_QUESTION_TYPE` | Тип не single/multiple, в том числе отсутствует                     |
| `OPTION_COUNT`          | Количество вариантов вне 2–6                                        |
| `DUPLICATE_OPTION_ID`   | Повтор нормализованного id                                          |
| `CORRECT_OPTION_COUNT`  | Неверное количество правильных вариантов                            |
| `NOT_INTEGER`           | Дробное число, NaN или бесконечность                                |
| `OUT_OF_RANGE`          | Целое число вне диапазона либо ID длиннее 256 кодовых единиц UTF-16 |

Порядок ошибок детерминирован: тип, содержимое, таймер, баллы, варианты по индексу, количество правильных ответов. Независимые нарушения возвращаются вместе. При недопустимом количестве вариантов зависимые ошибки отдельных вариантов и количества правильных ответов не формируются.

Тесты импортируют публичный index, проверяют успешные данные, коды, поля и непустые сообщения. Тестовые файлы исключены из сборки shared, но входят в отдельный строгий typecheck. Используется уже принятый Vitest 3.2.4; новых библиотек валидации нет.
