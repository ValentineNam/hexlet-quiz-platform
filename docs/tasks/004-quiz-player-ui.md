# Задача № 004 — адаптивный интерфейс прохождения квиза

Дата выполнения: 04.11.2026 (Europe/Moscow). ПМ01 — разработка программных модулей. Локальная демонстрация в apps/web, без серверной игровой сессии.

## Реализация

- Три вопроса в demo-quiz.ts: single про Марс (30 секунд, 1000 баллов), multiple про млекопитающих (20 секунд, 1500 баллов), single про треугольник (5 секунд, 500 баллов). Общий максимум — 3000. Все данные проверяются validateQuestion при загрузке модуля.
- App хранит результаты завершённых вопросов. QuestionRound отвечает за один вопрос, выбор, таймер и результат. Ключ попытки/индекса создаёт новый экземпляр при переходе и перезапуске. Summary показывает сумму, максимум, количество правильных ответов и вопросов.
- Single использует нативные radio, multiple — checkbox. Пустой выбор не отправляется. Проверка и начисление выполняются через evaluateAnswer из @quiz/shared; формула во frontend не повторяется.
- Результат включает правильность, полученные баллы, правильные варианты и объяснение. Синхронный ref-флаг settled блокирует повторную отправку независимо от задержки React-render. Fieldset и кнопка блокируются после результата. Родитель также проверяет индекс при добавлении результата.
- Добавлена только локальная зависимость workspace:\* на @quiz/shared. Vite alias и TypeScript paths ведут к исходному публичному index shared, чтобы pnpm dev не требовал предварительно собранного dist shared. Обычная сборка монорепозитория сохраняет порядок workspace-зависимостей. Контракты shared не менялись, новых внешних библиотек нет.

## Таймер и границы

Начало вопроса фиксируется через performance.now() при монтировании. Остаток — durationMs минус разница текущего и начального времени; интервал 100 мс только обновляет отображение. Событие visibilitychange также обновляет остаток. Отправка и изменение выбора повторно сверяют фактическое прошедшее время, поэтому задержанные интервалы не дают отправить просроченный ответ.

Утверждённое после аудита правило: при elapsedMs === durationMs ответ принимается, просрочка наступает только при elapsedMs > durationMs. Отправка выбранного ответа всегда оценивается evaluateAnswer; интервал, visibilitychange и изменение выбора используют тот же строгий предикат просрочки. При точном дедлайне остаток отображается как 0 секунд, но вопрос ещё не завершён: выбор и отправка выбранного ответа разрешены. Пояснение сообщает, что на точной границе ответ принимается, а при отправке время проверяется повторно. Уже при превышении дедлайна действие или следующий refresh переводит вопрос в timeout с 0 баллов и блокировкой управления. Интервал обновляет экран раз в 100 мс; между обновлениями вид кнопки не отменяет обязательную проверку фактического времени в обработчике. Общий finish синхронно фиксирует settled до React-render, останавливает таймер и сохраняет результат только один раз. Это предотвращает перезапись принятого ответа поздним refresh и двойное начисление. Повторная отправка и пустая программная отправка формы игнорируются (для пустой формы также проверяется просрочка). Контракты shared не менялись.

Cleanup удаляет интервал и обработчик visibilitychange при размонтировании; эффект проверен также в React StrictMode. При переходе создаётся новый таймер. Перезапуск очищает всю историю и выбор. Результаты хранятся только в памяти страницы; обновление страницы начинает квиз заново.

## Адаптивность и доступность

Светлая сетка из двух колонок на широком экране становится одной колонкой до 900 px. Для ширины до 430 px уменьшаются отступы. Использованы minmax(0, ...), min-width: 0, переносы длинных строк, гибкие подписи и отсутствие фиксированной ширины карточки. Минимальная целевая ширина — 320 px. Вертикальная прокрутка на узком экране нормальна; все варианты не обязаны помещаться в высоту одного экрана.

Семантика: header/main/aside/footer, section с заголовками, form/fieldset/legend, связанные через label поля. Клавиатурное поведение radio/checkbox нативное. Видимый focus-visible, перенос фокуса к вопросу, результату и итогам. Feedback объявляется через role=status; таймер не создаёт live-объявлений каждые 100 мс. Выбор и правильность различаются не только цветом: нативное checked и текст «Правильный». Варианты имеют высоту минимум 60 px, основная кнопка — 50 px. Тёмный текст на светлом фоне; формальный аудит WCAG и проверка скринридером не выполнялись. prefers-reduced-motion отключает переходы и анимацию.

## Граница демонстрационного режима

Правильные ответы входят в браузерный bundle только для локальной тренировки, и пользователь технически может увидеть их в исходниках. Надпись «Локальный деморежим» и пояснение о локальной проверке видны в интерфейсе. В настоящей многопользовательской игре правильные ответы, серверное время и начисление баллов должны оставаться на сервере до закрытия вопроса; этот frontend не является безопасным протоколом игровой сессии.

Нет авторизации, БД, WebSocket, комнат, синхронизации, API сессий, серверного таймера, редактора или сохранения результатов.

## Автоматические проверки

Проверяются данные, отображение вопроса/таймера/прогресса, radio, checkbox и снятие выбора, пустая отправка, вызов реального evaluateAnswer с 12000 мс и результат 875, неправильный/неполный ответ, timeout, задержанный интервал, visibilitychange, блокировка повтора, свежий таймер следующего вопроса, итоги, перезапуск, фокус и очистка таймеров в StrictMode. Контролируемое время: fake timers для interval/performance.

Браузерная проверка — установленный Chrome headless с отдельным временным профилем, без Playwright. Размеры, клавиатура, реальный timeout, reduced-motion и скриншоты описаны в [отдельном протоколе](../testing/004-ui-check-2026-11-04.md). Ручная проверка пользователем на реальном устройстве не заявляется.

Первоначальный прогон 04.11.2026: 295 тестов прошли (17 web, 277 shared, 1 API); frozen offline install, lint, typecheck, build, format:check и git diff --check успешны.
