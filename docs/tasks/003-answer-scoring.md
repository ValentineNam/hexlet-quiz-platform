# Задача № 003 — проверка ответов и начисление баллов

Дата выполнения: 04.11.2026 (Europe/Moscow). ПМ01 — разработка программных модулей. Основание: утверждённые пользователем правила задачи № 003. Прежнее предложение SCORE-04 заменено по этому согласованию; GAME-05 уточнён в части включённого дедлайна. Другие правила игры не менялись.

## Контракт

Модуль `packages/shared/src/answer-scoring.ts`, публичный экспорт через `packages/shared/src/index.ts`:

```ts
checkAnswer(question: unknown, selectedOptionIds: unknown): boolean;
calculateScore(maxPoints: unknown, durationMs: unknown, elapsedMs: unknown): ScoreResult;
evaluateAnswer(question: unknown, selectedOptionIds: unknown, elapsedMs: unknown): AnswerEvaluation;
```

Все входы проверяются на границе unknown; числовые строки и boolean не приводятся к числам. Публичные типы результата:

```ts
type ScoreResult =
  | { status: 'scored'; score: number }
  | { status: 'late'; score: 0 };

type AnswerEvaluation =
  | { status: 'accepted'; isCorrect: boolean; score: number }
  | { status: 'late'; score: 0 };
```

`checkAnswer` проверяет только правильность без учёта времени. `calculateScore` предназначена только для правильного ответа. `evaluateAnswer` объединяет обе операции, для неправильного ответа вовремя возвращает accepted / false / 0, для просроченного — late / 0 без признака правильности. Некорректные аргументы вызывают типизированное исключение, а не обычный неправильный ответ.

Используются существующие `Question`, `ValidationError` и `validateQuestion`. Новый доменный тип вопроса не создавался; контракт validateQuestion не менялся. Перед оценкой вопрос валидируется и нормализуется существующей функцией. Длительность берётся как `question.timeLimitSeconds * 1000`. Таймер и maxPoints нельзя брать из ответа участника.

## Утверждённая формула

```ts
score = Math.round(
  maxPoints *
    (1 -
      (0.5 * Math.max(0, elapsedMs - 0.2 * durationMs)) / (0.8 * durationMs)),
);
```

Применяется при `0 <= elapsedMs <= durationMs`. Первые 20% времени включительно дают полные баллы. Далее множитель линейно снижается от 1 до 0.5. Уточнение пользователя от 04.11.2026 после аудита: эталон — точное математическое значение формулы с округлением половин вверх для неотрицательного результата. Прямое вычисление выражения через number/Math.round не является эталоном из-за IEEE 754. Время не округляется и не ограничивается искусственно диапазоном. Из-за округления сразу после 20% целый балл может остаться максимальным.

## Алгоритм правильности

1. Проверить и нормализовать вопрос через validateQuestion; при ошибке выбросить AnswerScoringError с деталями валидатора.
2. Проверить, что выбор — массив не длиннее 100 элементов: длина проверяется до обхода и создания Set. Для evaluateAnswer затем проверить тип, конечность и неотрицательность elapsedMs. Проверить ID в ограниченном массиве (строка, не более 256 кодовых единиц UTF-16 до trim, непустота); разреженные позиции и неверные типы элементов — ошибки аргумента.
3. Создать Set выбранных id, устраняя повторы. Перед добавлением нового уникального ID проверить, что их ещё меньше шести; седьмой вызывает INVALID_SELECTION с путём элемента. Повторы в пределах общей длины 100 допустимы. Строки выбора сравниваются точно, без trim и смены регистра. Пробельный id недопустим; строка с пробелами вокруг непустого id считается другим id. Идентификаторы вопроса при этом уже нормализованы валидатором.
4. Получить варианты вопроса с isCorrect=true. Проверить равенство количества уникальных выбранных и правильных id и наличие каждого правильного id в выборе.
5. Для single у валидного вопроса один правильный id; для multiple — минимум два. В обоих случаях точное равенство множеств исключает частичный зачёт, лишние и неизвестные варианты. Порядок не влияет.

Сложность проверки: O(q + a + s) по вариантам вопроса, выбору и обрабатываемым строкам; q ограничено 2–6, a ограничено 100. Для заведомо слишком длинного массива проверка его длины — O(1), без обхода элементов. В Set не более шести ID длиной не более 256 кодовых единиц UTF-16. Проверка массива ответа ограничена 100 элементами; строки ID проверяются на длину до trim и хеширования. Входные объекты и массивы не изменяются. Внутренние Set и нормализованные данные создаются заново, I/O и состояние между вызовами отсутствуют.

## Ошибки и границы

Единый способ обработки некорректных аргументов — `AnswerScoringError extends TypeError`. Экспортируются также `AnswerScoringErrorCode` и `AnswerScoringField`. Исключение содержит `code`, `field`, русское `message`; для INVALID_QUESTION — `questionErrors` существующего формата ValidationError[].

| Код                | Поле                                        | Условие                                                                       |
| ------------------ | ------------------------------------------- | ----------------------------------------------------------------------------- |
| INVALID_QUESTION   | question                                    | Вопрос не прошёл validateQuestion                                             |
| INVALID_SELECTION  | selectedOptionIds либо selectedOptionIds[i] | Выбор не массив, длиннее 100, содержит неверный ID либо более 6 уникальных ID |
| INVALID_MAX_POINTS | maxPoints                                   | Не число, не целое или вне 100–2000                                           |
| INVALID_DURATION   | durationMs                                  | Не целое число миллисекунд, вне 5000–120000 или не кратно 1000                |
| INVALID_ELAPSED    | elapsedMs                                   | Не число, NaN, ±Infinity либо отрицательное значение                          |

Длительность соответствует доменному правилу 5–120 целых секунд: например, 5001 мс недопустимо. Дробное прошедшее время допустимо как конечное неотрицательное число (для будущего высокоточного серверного измерения); оно участвует в формуле без округления. `-0` эквивалентен нулю. При нескольких ошибках выбрасывается первая: вопрос → тип и длина массива выбора → время → типы и ограничения ID по индексу в evaluateAnswer; maxPoints → durationMs → elapsedMs в calculateScore. Даже для просроченного ответа выполняется обязательная проверка всех ID в массиве длиной до 100, иначе неверные аргументы скрылись бы за статусом late. После неё просрочка возвращается без сравнения правильности и без расчёта баллов. Заведомо огромный массив отклоняется до обхода, независимо от времени; некорректное время не превращается в обычный неправильный ответ.

| Вход/граница                            | Результат                                                     |
| --------------------------------------- | ------------------------------------------------------------- |
| elapsedMs=0                             | Полный балл для правильного ответа                            |
| Ровно 20%                               | Полный балл                                                   |
| Сразу после 20%                         | Формула, округлённый балл может ещё оставаться полным         |
| Ровно durationMs                        | Принимается, Math.round(maxPoints / 2) для правильного ответа |
| elapsedMs > durationMs                  | late / 0 независимо от правильности или пустого ответа        |
| Отрицательное elapsedMs, NaN, ±Infinity | INVALID_ELAPSED                                               |
| Дробное elapsedMs >= 0                  | Допустимо                                                     |
| Пустой массив ответа                    | Неправильно; вовремя 0, после дедлайна late                   |
| Неизвестный непустой строковый id       | Неправильно; вовремя 0                                        |
| Повтор правильного id в single          | Один уникальный id, ответ правильный                          |
| Повторы в multiple                      | Дедупликация; не восполняют пропущенные правильные варианты   |
| Иной порядок выбранных id               | Не влияет на multiple                                         |
| Только часть правильных или лишний id   | Неправильно, частичных баллов нет                             |
| 100/2000 баллов и 5/120 секунд          | Допустимые границы                                            |

Вопрос и результаты авторской проверки содержат правильные ответы. Их нельзя использовать как payload участника до закрытия вопроса. Произвольные getter/Proxy не изолируются, как и в модуле валидации. Время получения ответа в будущем определяет сервер; клиентское время недоверенное. Этот модуль не реализует дедлайны реальных сессий, транзакционность, защиту от повторной отправки или серверные часы.

## Завершающий рефакторинг после аудита — 04.11.2026

Точный расчёт после 20% использует алгебраически эквивалентное выражение `P × (9D − 5t) / (8D)`. Целочисленное t преобразуется в BigInt без потерь. Дробное t разлагается через биты binary64 на точную дробь N/Q: мантисса и степень двойки. Эталоном служит фактическое числовое значение переданного JavaScript number, а не исходная десятичная строка (которую функция не получает). Затем вычисляются числитель `P × (9DQ − 5N)` и знаменатель `8DQ`. Для неотрицательной дроби A/B округление половин вверх даёт `(2A + B) / (2B)` с целочисленным делением BigInt. Number создаётся только из окончательного целого балла, не превышающего 2000. Epsilon не используется.

Первые 20% проверяются как `elapsedMs <= durationMs / 5`; граница — точное целое, поскольку D кратно 1000. Просрочка проверяется до арифметики BigInt. Поэтому отрицательные/нечисловые аргументы отклоняются, очень большое конечное время даёт late, а величина промежуточных чисел для принятого дробного времени ограничена форматом binary64 и допустимой длительностью.

Исправлены регрессии `calculateScore(100, 5000, 4400) → 58` и `calculateScore(1000, 30000, 12168) → 872`. Дробный пример: при P=1024, D=5000, t=3136.71875 математический балл 750.5 округляется до 751; соседнее представимое большее время даёт 750.

Предел длины ID согласован пользователем дополнительно: 256 кодовых единиц UTF-16 в обоих модулях. Общая константа MAX_OPTION_ID_LENGTH экспортирована через shared. Длина исходной строки проверяется до trim, чтобы не обрабатывать заведомо слишком длинные значения. Для ID вопроса возвращается существующий OUT_OF_RANGE / options[i].id, для выбранного ID — AnswerScoringError с INVALID_SELECTION / selectedOptionIds[i]. Сигнатура, публичные типы и формат результата validateQuestion не изменены; новое ограничение ID явно согласовано пользователем.
