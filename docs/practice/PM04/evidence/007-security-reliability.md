В HTTP-телах проверялись отсутствие тестового пароля и маркеров PostgreSQL URL, DATABASE_URL, PrismaClient, query engine, stack. Публичные POST/GET и все успешные измеряемые ответы не содержали isCorrect. Сравнение GET с исходным POST подтвердило порядок и данные. В авторском входе isCorrect разрешён и необходим. Проверка не запрещала текст имени конфигурации в локальном stderr ошибки конфигурации: это не пароль и не HTTP-ответ.

PORT abc/0/65536/3000.5: exit1, запуск прекращён. Missing DATABASE_URL и URL с неверным протоколом: exit1. Недоступный PostgreSQL при старте: exit1, сообщение без URL/пароля. Для этих стартовых тестов не используется пользовательский .env: запускается node dist/main.js с явно собранным окружением. Локальные startup stack traces могут содержать пути исходников; в артефактах домашний путь обезличен. В HTTP-ошибках такого стека нет.

Остановка только тестовой БД проверена **после** измерений, без активных записей в момент stop. Подтверждённый квиз сохранился после нормального рестарта; это не тест power-loss/crash durability. API восстановил чтение и POST без перезапуска, отдельный повтор в этой серии не понадобился. Секрет тестового соединения не появился в stdout/stderr собственных работающих процессов по проверке скрипта.

## Доступ и статическая проверка

Слушающий API подтверждён lsof как 127.0.0.1, PostgreSQL docker port — 127.0.0.1. Default запуск без ENABLE_QUIZ_API и DATABASE_URL даёт health200 и GET /quizzes/:id404; исходный AppModule.configure(false) не подключает DB-модуль. API наружу не публиковался. Настройки auth/CORS не ослаблялись. Процедура не доказывает отсутствие доступа со стороны других локальных процессов.

Из tracked env-файлов найден только .env.example. Приватные ключи/типовые GitHub-токены по ограниченным regex-маркерам не найдены. Три PostgreSQL URL в tracked-тексте — .env.example и два URL CI, распознаны как шаблоны/disposable CI. В собранном frontend JS нет DATABASE_URL, POSTGRES_PASSWORD или postgresql://. Поиск не читает локальный .env и не является исчерпывающим secret scanner, dependency audit или пентестом.

Новых подтверждённых дефектов корректности/потери данных в ограниченной серии не найдено. Первый сбой восстановления был ошибкой стенда с переменным Docker-портом; на фиксированном порту восстановление подтверждено. Короткий RSS-рост не классифицируется как утечка памяти.
