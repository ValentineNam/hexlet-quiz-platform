## Порядок проверок и просрочка

- checkAnswer: вопрос → тип/длина массива → ID по индексу (тип, длина, непустота, число уникальных) → правильность.
- calculateScore: maxPoints → durationMs → elapsedMs → просрочка → точный расчёт.
- evaluateAnswer: вопрос → тип/длина массива → elapsedMs → ID по индексу → просрочка → правильность → точный расчёт только для правильного ответа.

Массив длиной более 100 немедленно даёт INVALID_SELECTION без чтения элементов и создания Set выбранных ID, включая просроченные ответы. У массива в пределах лимита обязательная проверка ID выполняется и при просрочке, иначе некорректные аргументы могли бы скрыться за late. Её стоимость ограничена 100 элементами и шестью уникальными строками длиной не более 256 кодовых единиц UTF-16. Затем late возвращается без проверки правильности и расчёта баллов.

Проверки не означают интеграцию с серверными часами, API, WebSocket или БД. Коммиты и push не выполнялись.
